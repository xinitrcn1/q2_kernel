# q2k

A small C99 inference kernel and CLI for Granite 4.0-H Tiny
(`granitehybrid`) in GGUF, built with BSD make.  The model file is
mmapped read-only; nothing is copied at load except what goes to the GPU.

    make
    ./q2k -p "The capital of France is" -n 32        # completion
    ./q2k -i                                         # chat (model template)
    ./q2k -g 0 ...                                   # CPU only
    ./q2k --bench -p "..."                           # speed + time breakdown

Default model: `~/mb/granite-4.0-h-tiny-UD-Q2_K_XL.gguf` (or `-m`,
`$Q2K_MODEL`).  Dependencies: libc, pthreads, the Vulkan loader and
headers, and glslangValidator at build time.

## Layout

| file | |
|---|---|
| `src/gguf.c` | bounds-checked GGUF v2/v3 reader over the mmap |
| `src/quant.c` | reference dequantization (Q2_K..Q6_K, Q8_0), bit-exact with ggml; f32 reference dot (`--ref`) |
| `src/kq.c` | optimized CPU dots: activations quantized to 8-bit blocks of 256 (`q8k`), integer dots with AVX2 (scalar twin kept for checking) |
| `src/vmath.c` | AVX2 exp/SiLU/norm/dot helpers |
| `src/model.c` | forward pass: Mamba2 mixer (head split), NoPE GQA attention, top-6-of-64 MoE + shared expert; matvec batches over the CPU pool and the GPU |
| `src/prefill.c` | batched prompt processing |
| `src/vk.c`, `shaders/*.comp` | Vulkan compute: resident weight arena and state, two command slots, DP4A matvec (decode) and tiled GEMM (batches) per quant type, conv/scan/quantize ops |
| `src/tok.c`, `src/ucd.c` | byte-level BPE tokenizer (llama3/dbrx pre-split); `ucd.c` generated by `make ucd` |
| `src/pool.c` | pthread pool (spin-then-block, dynamic chunks) |

## CPU/GPU split

`-g MIB` (default 512) is the weight budget on the GPU; `--split F`
(default 0.5) the GPU's share of split work.  Placement is decided once
at load and stays resident; nothing is uploaded while decoding.  In
order, until the budget is spent:

1. **Mamba2 mixers, resident in full** (projections, conv, norms, the
   conv/SSM state of every head).  While decoding the GPU computes heads
   `[0, hg)` (`--split` of them) and the CPU the rest, concurrently;
   a prompt batch runs every head on the GPU.  The gated RMS norm only
   rescales `ssm_out`'s input, so each side returns `ssm_out(y*w)` over
   its columns plus a sum of squares and `out = (gpu + cpu) / rms(y)`:
   one GPU round trip per mixer, both memory systems streaming.
2. attention projections and shared experts, whole;
3. the leading `--split` of the tied output projection's rows (the CPU
   does the rest concurrently);
4. routed experts as gate+up+down triples, the same number per layer.

Per layer the GPU gets two submits (mixer half; resident experts as
gate/up -> SwiGLU -> down) that run alongside the CPU's work.  All device
memory stays within `--vram` (default 1280 MiB, the GPU is shared with
the desktop) and the driver's heap budget; a larger `-g` is clamped.

GPU weights are the GGUF blocks repacked to 4-byte alignment; the
shaders take the CPU path's `q8k` activation blocks and use packed
4x8-bit dot products (`GL_EXT_integer_dot_product`), with an emulated
variant for devices without it (`Q2K_NO_DOT=1` forces it).

## Prompts

Prompts run in chunks of up to 128 tokens (`src/prefill.c`), two at a
time:

- every resident Mamba2 mixer runs all heads on the GPU as a tiled
  int8 GEMM (`shaders/mmq.comp`: 32 rows x 32 tokens per workgroup,
  each weight block decoded once into shared memory, DP4A micro-tiles)
  plus batched conv and scan (one workgroup per head, B/C staged in
  shared memory); the CPU heads' state is synced over and back;
- the shared expert runs on the GPU, routed experts on the CPU
  (`kq_dotT`: each block decoded once for all of the expert's tokens);
- chunk A's experts (CPU) overlap chunk B's mixer (GPU) and vice versa,
  using two GPU command slots;
- the 4 attention layers run on the CPU.

`--no-batch` feeds token by token; `Q2K_PREFILL_PROF=1` times phases.

## Performance (this host: i5-9400, GT 1030, shared desktop)

| | tok/s |
|---|---|
| decode, `-g 512` | ~44 |
| decode, CPU only | ~30 |
| prompt (352 tokens), `-g 512` | ~200-220 |
| prompt, CPU only | ~120 |
| llama.cpp CPU decode, same host | 10-16 |

`--bench` prints a time breakdown; `Q2K_GPUPROF=1` adds per-stage GPU
timestamps.  Pool and fence waits spin up to 100 ms before sleeping:
with deep C-states, cores woken from sleep ran CPU matmuls 3.5x slower.

## Checking

- `--check`: every quant type on CPU (scalar integer, AVX2) and GPU
  against the f32 reference.
- `--kbench`: single-thread CPU kernel throughput per type.
- `--logits`, `--dump FILE`: next-token logits for comparison with
  llama.cpp (`llama-logits`); greedy output matches llama.cpp on the
  test prompts, and per-layer values agree to ~4 digits through layer 5
  (`Q2K_TRACE=1` prints llama.cpp-style tensor sums).
- `tools/bench.sh`: best-of-N interleaved speed runs (the host is shared).

The word-level 6-bit scale unpacking in `kq.c` and the exp polynomial in
`vmath.c` were derived/proved with ucas (SAT equivalence; minimax fit),
and `v_exp` was checked against double `exp` over all 2.24e9 floats in
its range (max 0.909 ulp).
